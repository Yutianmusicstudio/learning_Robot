## 本课要点亮的四件事

1. **引脚是"信号"，不是"电源"** —— 这一条决定了你不会在第二周烧掉板子
2. **PWM 不是把电压调低** —— 这一条决定了你的电磁铁烫不烫
3. **`delay()` 是瘫痪，不是等待** —— 这一条决定了你能不能弹和弦
4. **状态机** —— 你的第一段真正的机器人代码

第 3 条是本课的核心。**你会先失败一次，这是故意安排的。**

## 课前 · 三个新手真实会栽的坑

### 坑 1：面包板的孔是怎么连通的

```
上下两条长横排（红蓝线）：整排横向连通 —— 电源轨
中间的竖列：每 5 个孔一组，纵向连通
中间那道沟：左右两侧不连通（这道沟是给芯片跨的）
```
插错方向，什么都不会亮，而且看不出毛病。**先记住这张图。**

### 坑 2：LED 有极性
**长脚 = 正极（接电阻/引脚一侧），短脚 = 负极（接 GND）。**
接反了不亮，但不会坏，放心试。

### 坑 3：电阻不能省
省掉电阻 = 烧 LED 或烧引脚。原因在实验 1 里算给你看。

## 第一节 · 引脚不是电源（实验 1，20 分钟）

烧录 [`L01_1_blink`](../../code/lesson01/L01_1_blink)。

接线：`D8 --[220Ω]-- LED长脚 ... LED短脚 -- GND`

灯闪起来只是开始。**真正的任务是拿万用表量三个电压并记下来**：

| 测量点 | 你的读数 | 应该是 |
|---|---|---|
| D8 对 GND（灯亮时） | ______ V | ≈ 5 V |
| 电阻两端 | ______ V | ≈ 3 V |
| LED 两端 | ______ V | ≈ 2 V |

然后自己算一遍：

```
流过 LED 的电流 = 电阻两端电压 ÷ 电阻值
                = 3.0 V ÷ 220 Ω
                ≈ 13.6 mA
```

Arduino 单引脚上限约 **20 mA**。13.6 < 20，所以安全。

### 这一节真正的结论

电阻的作用**不是降压，是限流**。

而电磁铁需要 **500 mA**，是引脚上限的 **25 倍**。
没有任何电阻能救它——你必须换一种思路：
**用引脚去"开关"一个 MOSFET，让大电流从电源直接走 MOSFET，根本不经过 MCU。**

这就是第二课要做的事。今天你只需要建立这个直觉：
> **引脚发号施令，不干体力活。**

## 第二节 · PWM 不是把电压调低（实验 2，15 分钟）

把 LED 从 D8 改接到 **D9**（必须是板上带 `~` 的 PWM 引脚：3, 5, 6, 9, 10, 11）。

烧录 [`L01_2_pwm`](../../code/lesson01/L01_2_pwm)，用万用表测 D9：

| 占空比 | 你的读数 | 应该是 |
|---|---|---|
| 0 % | ______ V | ≈ 0 |
| 25 % | ______ V | ≈ 1.25 |
| 50 % | ______ V | ≈ 2.5 |
| 100 % | ______ V | ≈ 5 |

### 关键理解（这一条错了，后面全错）

万用表读到 2.5V，**不代表引脚在输出 2.5V**。

引脚一直在 0V 和 5V 之间高速切换（UNO 上约 490 Hz），只是有一半时间是高电平。
**万用表读的是平均值。** 有示波器的话，你会看到方波，不是一条直线。

### 为什么这件事对本项目至关重要

电磁铁的发热 ≈ **平均**功率。
占空比降到 35%，发热就降到约 35%；但因为线圈有电感（电流来不及归零），
**吸持力衰减得比发热慢得多**。

这就是 peak-and-hold 能"既吸得住又不烫"的物理原因。

> 顺带一个陷阱：人眼对亮度的感觉是非线性的，占空比 50% 看起来远比"一半亮"要亮。
> 所以后面做力度标定时，**不能靠眼睛和耳朵的直觉，必须靠测量。**

## 第三节 · `delay()` 的陷阱（实验 3，20 分钟）★ 本课核心

### 任务
LED_A 每 500 ms 翻转一次，LED_B 每 300 ms 翻转一次，**各闪各的，互不影响**。

接线：`D8 --[220Ω]-- LED_A -- GND`，`D9 --[220Ω]-- LED_B -- GND`

### 先自己写，不要看代码

给自己 10 分钟，用你现在会的东西（`digitalWrite` + `delay`）试着做出来。

**你会失败。这是故意的。** 失败过一次，你才会真的记住下面这句话。

烧录 [`L01_3_delay_trap`](../../code/lesson01/L01_3_delay_trap) 看看典型的失败长什么样：
两个灯在**排队**，而且 A 的周期变成了 1600ms，根本不是你要的 1000ms。

### 为什么

`delay(500)` 的真实含义是：

> **"这颗 CPU 接下来 500 毫秒什么都不做，只是空转数数。"**

在这 500 ms 里，B 不能被处理，串口不能被读取，什么都不能发生。

**`delay()` 不是"等待"，是"瘫痪"。**

### 这对钢琴机器人意味着什么

一个和弦 = 3 个键同时按下，各有各的击打时长和松开时刻。
8 个键 = 8 套互相独立的计时。

**用 `delay()`，一个都做不到。**

> 从今天起，你的项目代码里不再出现 `delay()`。
> （实验 1、2 用了，那是教学脚手架，现在拆掉。）

## 第四节 · 非阻塞（实验 4，15 分钟）

烧录 [`L01_4_millis`](../../code/lesson01/L01_4_millis)。同一个任务，这次真的做到了。

### 思路的转变

| | 想法 |
|---|---|
| `delay` 的思路 | **"现在等 500 毫秒"** —— 命令时间 |
| `millis` 的思路 | **"现在几点了？到点了就做"** —— 查看时间 |

`millis()` 返回开机到现在的毫秒数，是一个一直在走的钟。
你不去停住它，只是不停地问它"到点了吗"。

```cpp
uint32_t now = millis();

if (now - lastA >= PERIOD_A) {   // A 到点了吗？
  lastA = now;
  stateA = !stateA;
  digitalWrite(LED_A, stateA);
}

if (now - lastB >= PERIOD_B) {   // B 到点了吗？（和 A 完全独立）
  ...
}
```

`loop` 在这里飞快转圈，每秒几万次，从不停下。
**所以任何时刻、任何一个任务到点了，都能被立刻处理。**

### 两个必须照抄的细节

1. **写 `now - last >= PERIOD`，不要写 `now >= last + PERIOD`。**
   `millis()` 约 49.7 天溢出归零；减法形式利用无符号回绕，溢出时依然正确，加法形式会出错。
2. **变量必须用 `uint32_t`，不能用 `int`。**
   UNO 的 `int` 只有 16 位，最大 32767，**32 秒就溢出**。

### 验证你真的懂了
加第三个 LED，周期 137 ms。三个灯应该毫无关系地各闪各的。
**做得到，你就掌握了本项目最重要的编程概念。**

## 第五节 · 状态机（实验 5，20 分钟）

烧录 [`L01_5_state_machine`](../../code/lesson01/L01_5_state_machine)，打开串口监视器（115200），输入 `p`。

你会看到：**LED 猛地全亮 0.5 秒 → 明显变暗持续 2.5 秒 → 熄灭。**

### 这就是 peak-and-hold

```
IDLE ──输入p──> PEAK ──25ms后──> HOLD ──到时间──> IDLE
空闲            全功率           35%功率          断电
                "击打"           "按住"
```

代码里用了 `SLOW_MOTION = 20` 做慢放，因为真实的击键只有几十毫秒，眼睛看不见。

### 这段代码的分量

**它和 [`code/phase0_single_solenoid`](../../code/phase0_single_solenoid) 几乎一模一样。**
等电磁铁到货，你只需要：把引脚改到 MOSFET 的栅极、把 `SLOW_MOTION` 改回 1。

**今天写的不是练习，是 Phase 0 的正式代码。**

### 三个练习

1. 把 `SLOW_MOTION` 改成 `1`。现在你几乎看不见 PEAK 阶段了——**这才是真实的时间尺度**，感受一下 25 毫秒有多短。
2. 把 `HOLD_DUTY` 改成 20，再改成 200。将来这个值就是"电磁铁烫不烫"的旋钮。
3. ★ **把它改成同时驱动两个 LED**（D9 和 D10），`p` 触发第一个、`q` 触发第二个，两者完全独立、可以重叠。
   —— 做出来的话，你已经写出 Phase 1 的骨架了。

## 常见错误速查

| 现象 | 原因 |
|---|---|
| LED 完全不亮 | LED 装反了（长脚是正极）／面包板插到了不连通的孔／忘了 `pinMode(..., OUTPUT)` |
| `analogWrite` 只有全亮和全灭，没有中间亮度 | 接的不是 PWM 引脚。必须用板上带 `~` 的：3, 5, 6, 9, 10, 11 |
| 串口监视器全是乱码 | 波特率没设成 115200 |
| 输入 `p` 没反应 | 串口监视器右下角的行结束符设成"换行"或"没有结束符"都行，但要确认真的发出去了 |
| 计时几十秒后就乱 | 变量用了 `int`，改成 `uint32_t` |
| 灯亮着就一直不灭 | 状态机里漏了从 HOLD 回到 IDLE 的那个判断 |

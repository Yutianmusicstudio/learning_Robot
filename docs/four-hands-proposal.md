# 四手联弹机器人 · 项目方案

**定位**：在 Wang, Zhang & Iida, *Human–Robot Cooperative Piano Playing With Learning-Based Real-Time
Music Accompaniment*（**IEEE T-RO 40, 2024**）的基础上，把人机钢琴协作从**即兴伴奏**推进到**四手联弹**。
**执行**：Georgia Tech（The Hive / FIS）· 个人主导 · 寻求实验室支持
**版本**：v1 · 2026-09

> 本文取代 `project-proposal.md`、`mini-shimon-piano.md` 与 `proposal-ensemble-robot.md` 的目标定义。
> 那些文档中的 BOM、块状清单、硬件路线仍然有效——硬件本身没变，变的是它服务的问题。

---

## 一、出发点：一个带六条自述局限的 "first instance"

剑桥的系统（UR5 + 软硬混合拟人手，Kawai ES8 数字钢琴，MATLAB）让人弹旋律、机器人弹和弦伴奏，
自称是"第一个专为与人协作弹钢琴而设计的机器人"。**论文自己写明的局限：**

| # | 原文 | 本质 |
|---|---|---|
| 1 | "Due to hardware limitations, we simplified the tuning system" → **共 7 个和弦** | 覆盖范围 |
| 2 | "UR5 is not agile/fast enough" → 换和弦要从击键时间里挪补横移 | 速度 |
| 3 | "Only when all 16 tokens … have been fed into the RNN can the model give a chord prediction … **resulting in a lag**" | **架构性一拍延迟**，因为只靠 MIDI |
| 4 | "Evaluating whether a listener 'enjoys' the music involves psychological and subjective analysis" → 推迟 | 评估 |
| 5 | 未来工作："Enhancing the dexterity of the end-effector is crucial" | 灵巧度 |
| 6 | 未来工作：给 UR5 加距离/力传感器防止撞人 | **安全** |

**而且它做的是 homophony（旋律 + 和弦），训练于流行歌。它不是在合奏一首写定的曲子。**

## 二、核心主张：换问题类别，不是做大

| | 剑桥 | 本方案 |
|---|---|---|
| 问题 | **即兴**：为未知旋律生成和弦 | **合奏**：演奏写定的四手联弹第二声部（secondo） |
| 曲目 | 流行歌，7 个和弦 | 舒伯特 / 勃拉姆斯 / 柴可夫斯基 / 福雷 / 拉威尔的四手联弹文献 |
| 难点 | 弹**什么** | **何时、如何**与人一起弹——rubato、句法、呼吸、踏板 |
| 人的角色 | 提供旋律 | **primo 演奏者**，主导速度与表情 |

**"弹什么"是生成问题，"怎么跟你一起弹"是合奏问题。** 后者是室内乐的核心技艺，而且它需要一个演奏者来定义什么算"在一起"。

## 三、三项扩展，逐条对应剑桥的局限

### 扩展 A · 全覆盖固定执行器阵列（对应局限 1、2、5、6）

**决定性的简化**：四手联弹里 secondo 覆盖键盘下半部。**一个覆盖约 40 键（C1–E4）的固定电磁铁阵列，
就是一台完整的 secondo 机器人。** 不需要机械臂、不需要轨道、不需要运动学。

| 剑桥的局限 | 固定阵列的回答 |
|---|---|
| 7 个和弦 | 音域内任意音符、任意和弦 |
| UR5 太慢 | 电磁铁约 10ms 响应，**没有横移** |
| 端效器不够灵巧 | 每个键一个执行器，**没有灵巧度问题** |
| 安全 | **除了琴键没有任何东西在动**；人的手在另一半键盘上 |

**外加一个延音踏板电磁铁**——它解决了固定阵列的根本约束（手指按住时被锁死）：踏板抬起制音器，音符延续，执行器立刻释放。

### 扩展 B · 合奏跟随 + 视觉预判（对应局限 3）

- **跟谱（score following）**：机器人持有 secondo 的谱面，实时对齐人的 primo 演奏位置，按人的速度与表情输出。
  **这是成熟领域**（Raphael 的 *Music Plus One*、IRCAM 的 *Antescofo*、近年的神经跟谱器）——**本方案不声称算法新，声称的是把它放进"共享物理乐器 + 执行器延迟 + 踏板"的约束里。**
- **视觉预判**：剑桥只有 MIDI，所以必须等音发出才知道。钢琴家的手在触键前 100–300ms 已在移动。
  一个俯视摄像头 + 手部关键点 → 在触键前预测 → 抵消执行器延迟与跟谱延迟。
  技术存在（Shimon 的视觉节拍跟踪；FürElise / SKY-Piano / PianoVAM 提供训练数据），**应用于共享键盘上的击键级预判是本方案的集成点**。

### 扩展 C · 评估（对应局限 4）

剑桥推迟的那一项，本方案分三层做：

1. **客观**：人—人 vs 人—机的合奏不同步量（asynchrony），方法照抄 2021 年钢琴家 hyperscanning 研究的行为学部分
   （独奏自发速度差预测二重奏不同步）。
2. **演奏者视角**：搭档体验量表——**这个领域几乎所有评估都是听众视角，几乎没有"和它合奏的人怎么感受"**。
3. **神经（可选，第二阶段）**：人—机 EEG hyperscanning，与 2021 年人—人基线直接对比。

## 四、必须现在定的技术决定

| 决定 | 选择 | 理由 |
|---|---|---|
| 机器人弹哪个声部 | **secondo（下半）** | 与剑桥的"机器人 = 左手伴奏"一致；secondo 通常是节奏与和声骨架，对表情自由度要求较低；后期可交换角色作为实验 |
| 执行器 | **固定电磁铁阵列，约 40 键 + 踏板** | 见扩展 A。这就是硬件路线里已有的电磁铁阵列，扩到 40 |
| 琴 | **有 MIDI OUT 的锤感数字钢琴**（开发期） | 能把双方实际弹了什么回读验证；后期可上 Disklavier 或声学琴 |
| ★ 混合 MIDI 的分离 | **键盘分区（split）到不同 MIDI 通道** | 共享键盘上人和机器人的音符混在同一条 MIDI 流里。多数数字钢琴支持分区到独立通道；备选是机器人减去自己已知的指令 |
| 输入 | MIDI（第一阶段）→ MIDI + 俯视摄像头（第三阶段） | 先把跟随做对，再加预判 |
| 曲目 | **测试**：柴可夫斯基《50 首俄罗斯民歌》四手联弹（短、简单、多）<br>**演示**：舒伯特《军队进行曲》D.733 No.1 / 勃拉姆斯《匈牙利舞曲》No.5 | 前者适合批量实验，后者观众认得 |

## 五、分阶段（按学期）

```
阶段 0 · 纯软件（现在 → 秋季中）
   数字钢琴 MIDI → 跟谱 → 通过 MIDI 让琴自己发 secondo 声部
   零硬件。证明"合奏跟随"成立。这是最快能给 Gil 看的 demo。

阶段 1 · 硬件（秋季 → 春季初）
   电磁铁阵列 8 → 24 → 40 键 + 踏板 + 自制驱动 PCB
   （= 现有硬件路线的块状清单，扩到 40）

阶段 2 · 集成与首轮评估（春季）
   人—人 vs 人—机不同步量；搭档体验量表
   ↑ 到这里已经可以成文

阶段 3 · 视觉预判（春季末 → 夏）
   俯视摄像头 → 击键前预测 → 延迟对比（MIDI-only vs MIDI+vision）

阶段 4 · EEG（可选，夏 → 下一学年）
   人—机 hyperscanning vs 2021 人—人基线
```

**每一阶段可独立成文。阶段 0 不花钱、不需要新硬件，且它本身就完成了"即兴 → 合奏"的问题转换。**

## 六、风险

| 风险 | 程度 | 对策 |
|---|---|---|
| 跟谱算法成熟，被质疑"无算法贡献" | 高 | **从一开始就不声称算法新**。贡献是问题转换 + 物理集成 + 评估 |
| 剑桥组或他人先做四手联弹延伸 | 中 | 每季度重查；阶段 0 尽快出可见成果 |
| 共享键盘的 MIDI 混流 | 中 | 键盘分区；或已知指令减法；实测两种 |
| 固定阵列在真钢琴上力不够 | 中 | 开发期用数字琴；上真琴时换更大推力型号 + peak-and-hold |
| 规模 | 高 | 阶段划分严格；**阶段 2 结束即可成文，不依赖 3、4** |
| 执行者是表演出身，硬件是转行 | 中 | 阶段 0 全是软件；硬件走已有的块状清单；用 The Hive 的设备与人 |

## 七、明确的非目标

- ❌ 机器人弹 primo（旋律）——第一版不做，留作角色交换实验
- ❌ 移动臂 / 轨道——固定阵列已覆盖 secondo 所需
- ❌ 88 键——40 键覆盖 secondo
- ❌ 即兴——这是剑桥做的事，本方案刻意不做
- ❌ 表情头 / 脸——形式服从主张；本方案的社会性来自共享乐器本身

## 八、给 Gil 的一段话

> 剑桥 2024 年在 T-RO 发了第一台人机协作钢琴机器人。它只会 7 个流行和弦、机械臂不够快、
> 只靠 MIDI 所以慢一拍，而且他们自己说"好不好听"没法评。我想在它基础上做真正的四手联弹：
> 机器人弹 secondo，用一个固定电磁铁阵列覆盖下半键盘——不需要臂，所以没有速度和安全问题；
> 用跟谱让它跟着 primo 的 rubato 走；再加视觉预判抵消延迟。评估上，我是钢琴表演出身，
> 可以从演奏者视角测"搭档感"，后期用 EEG 和 2021 年那篇人—人 hyperscanning 直接对比。
> 阶段 0 纯软件，这学期就能给你看 demo。
